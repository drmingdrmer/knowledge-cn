# 依赖完备性：每对不可交换命令都由依赖路径排序

依赖完备性（Conflict Coverage）是一项系统约束：每对不可交换的命令实例，在命令 DAG 中都必须有一条从其中一个实例到另一个实例的有向路径。

## 推导：不可比的命令对都必须可交换

系统先选定[[command-commutativity|可交换性]]所保持的结果：仅最终状态，或者最终状态与逐命令返回值。只要一对命令在模型允许的某个起始状态下，交换顺序会改变约定的结果，依赖图就必须将这一对命令排序。

因此，依赖完备性也可以表述为：DAG 中每对不可比的命令都可交换。两种表述互为逆否命题。

这里的先后关系由[[topological-order-and-linear-extension|有向路径]]决定。图中已有 `A → B → C` 时，`A` 与 `C` 已经有序，依赖生成器可以省略直接边 `A → C`。系统也可以给可交换命令添加额外的依赖路径，只是会减少可并行执行的机会。

## 例子：加法与乘法需要确定先后关系

例如，计数器从 `0` 开始，“加 2”后“乘 3”得到 `6`，“乘 3”后“加 2”得到 `2`。依赖生成器必须给这两个实例确定一个方向，并保持整个图无环。

## 补充：依赖生成规则须保证完备性

系统需要证明依赖生成规则始终满足依赖完备性。DAG 的无环性只保证存在合法执行顺序；依赖完备性还要求依赖路径覆盖所有不可交换的命令对。
