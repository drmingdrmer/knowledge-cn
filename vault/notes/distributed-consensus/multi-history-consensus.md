# 多历史 consensus：历史树上的分布式一致性

应用以整棵历史树为状态时，在固定成员、只增存储、确认前持久化与读写 Quorum 相交的模型中，唯一追加和并集合并构成多历史 consensus：已提交历史单调增长，并能被后续 Quorum 读取。

## 一致性规范：已提交历史只增，完成写入后可读

初态为共同空根。把截至某时刻所有已完成写入携带的记录取并集，称为 `committed_history`。本文的多历史一致性要求这份历史始终是一棵合法的只增历史树，每次完成的 Quorum 读取都包含在其发起前已提交的全部记录。

读取者直接返回历史并集，`committed_history` 用于陈述其可见性保证。

应用允许多条历史分支共同构成状态。完成条件采用[[multi-history-commit|多历史提交]]的定义；请求在能收齐所需读写 Quorum 的成功回复时完成。

## 证明：四个已证性质组合成多历史协议

采用第九组的读写协议：接收端基于当前历史，原子地以 `stored_history ∪ incoming_history` 更新本地树，持久化成功后才确认。

1. 根据[[concurrent-history-appends|并发追加的兼容性]]，各 writer 产生合法且可合并的历史树。因此，已完成写入的记录并集仍是合法历史树。
2. 根据[[monotone-union|单调合并]]，每次本地合并都保留旧记录。将新增的完成写入并入 `committed_history`，同样保留全部旧记录；同一批记录的合并结果也一致。
3. 根据[[quorum-visibility|Quorum 可见性]]，先前已完成的每次写入都会出现在后发起的完成读取中。逐次应用这个结论，读并集就包含读取发起前的整个 `committed_history`。
4. 根据[[history-carry-forward|历史承接]]，在前次写入完成后才开始读取的新 writer，构造并写出的整棵树继续包含前次已写入的历史。

这些性质证明，第九组协议已经实现本文定义的多历史一致性。

## 例子：两条并发分支都成为已提交历史

两个 writer 从同一空根分别追加 `left` 与 `right`，各自完成写 Quorum 的持久化确认。两次提交完成后，后续完成的 Quorum 读取同时包含 `root → left` 与 `root → right`。应用接受这棵分叉树作为状态，就已获得多历史一致性。

## 保证范围：已提交历史是读结果的下界

这里的单调性指已提交历史按记录包含关系增长。读取可以同时带回尚未提交的临时分支；本定理承诺每次读结果包含读取发起前的已提交历史。
