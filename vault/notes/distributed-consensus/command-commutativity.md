# 命令可交换性：交换执行顺序保持最终状态

只比较最终状态时，命令可交换性（Command Commutativity）也称为状态可交换性（State Commutativity）：从模型允许的每个起始状态出发，先后执行这两条命令的两种顺序都会得到相同的最终状态。

## 判定：比较两种顺序的状态与逐命令返回值

这里将命令建模为确定的状态转移：命令根据当前状态产生下一状态和本次返回值。转移在模型允许的状态上都有定义，失败也作为明确的返回值处理。若系统使用有前置条件的命令，还必须保证两种顺序均可执行。

若还要求客户端观察到的返回值相同，就需要更强的语义可交换性（Semantic Commutativity）：交换顺序后，最终状态相同，而且每个命令实例各自的返回值相同。返回值应按命令标识比较，因为交换顺序也会改变返回事件的排列顺序。

## 例子：两种顺序都使计数器增加 5

例如，“给计数器加 2”和“给计数器加 3”具有状态可交换性。两种顺序都会让计数器在原值上增加 5。

## 例子：相同终态可以对应不同的逐命令返回值

例如，命令 `A` 和 `B` 都执行“加 1，并返回新值”。计数器从 `0` 开始时：

- 顺序 `A, B` 得到终态 `2`，返回值为 `{A: 1, B: 2}`。
- 顺序 `B, A` 得到终态 `2`，返回值为 `{A: 2, B: 1}`。

这两条命令满足状态可交换性。若返回值属于要保持的结果，两条命令就存在冲突。相对地，向两个独立键分别写入固定值，并各自返回固定的成功标记，可以同时保持终态与逐命令返回值。

## 补充：冲突判定与执行证明采用同一种结果语义

依赖图的冲突判定必须选定一种结果语义，并在依赖生成和执行证明中始终使用同一种语义。
